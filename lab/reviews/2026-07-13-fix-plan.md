## Workstream A — Mechanical bugs (∥ safe to start immediately)

`requirements-analyst.md` (frontmatter `name: requirements`). Doctor can never pass.
- Fix: change `requirements` → `requirements-analyst` in `need_agents`.
- Also reconcile with `setup.sh:68` verify block so both health checks test the same file set —
  make both derive from the same list: every `agents/*.md` basename except `README`.
- Accept: fresh `./setup.sh && ./scripts/eaos-doctor.sh` reports no missing agents.

### A2. `setup.sh` gaps (bug, verified)
- Install `commands/triage.md` (currently only agentic-os + incident are installed → `/triage`
  is undeliverable).
- Seed memory: copy `memory/index.md` + `memory/README.md` into `~/.claude/eaos/memory-seed/`,
  AND update `commands/agentic-os.md` Step 0 so the runtime `mkdir` also copies the seed
  `index.md` into `.eaos/memory/index.md` when absent (memory/README.md:28 claims index.md is
  "always loaded" — make Step 0 explicitly read it too).
- Clobber safety: before each `cp -f` over an existing user file, save `<file>.bak` once
  (or skip identical files). Note in output which files were backed up.
- Pin `agency-agents` clone to a specific commit SHA (add `AGENCY_SHA` var, `git checkout $SHA`
  after clone) so upstream pushes can't silently change the installed agent set.
- Accept: fresh install on a clean `$CLAUDE_HOME` gives `/triage`, seeded memory instructions,
  zero doctor failures; re-run over a modified install leaves `.bak` files instead of silent loss.

### A3. Artifact/memory path schism (bug, verified)
Kernel canon: `.eaos/<task-id>/artifacts/…` and `.eaos/memory/…` (routing.yaml:263-269,
protocol.md:44). But 15 agent files write bare `artifacts/<task-id>/…` or `memory/…`.
- Standardize EVERY agent file to the `.eaos/` forms: architect, code-reviewer, developer,
  qa-engineer, requirements-analyst, verifier, security-reviewer, devops-engineer,
  platform-engineer, sre-observability, tech-writer, ceo-strategist, product-manager,
  finance-analyst, growth-lead (and check incident-commander).
- Template refs in agents stay as `templates/…` (they resolve from `~/.claude/eaos/`); only
  runtime state paths change.
- Accept: `grep -rn "artifacts/<" agents/ | grep -v ".eaos/"` returns nothing;
  `grep -rn "memory/" agents/ | grep -v ".eaos/memory"` returns only template/config refs.

### A4. Mandatory gates owned by un-rostered agents (bug)
`routing.yaml` `launch_review` (owners: security-reviewer, sre-observability; required for any
standard+ feature) and `design_review` (three lenses) can fire when their owners were never
routed in.
- Add to `routing.yaml` under `autonomy`: `gate_owners_auto_roster: true` with a comment, and
  spell it out in `commands/agentic-os.md` Step 2: "if a required governance gate's owner is
  not on the roster, add them for that gate only."
- `playbooks/release.md`: add `tech-writer` to the `optional` roster (it's named in the
  STABILIZE phase table but absent from the roster block).
- Accept: text present in both files; `make validate` green.

### A5. Incident artifact chaos (bug)
- Delete `templates/incident-report.md` (orphan — zero references; `incident-rca.md` is the
  real template).
- Unify the RCA home to ONE path: `.eaos/incidents/<incident-id>/RCA.md`, with a one-line
  pointer file written to `.eaos/memory/lessons/<incident-id>.md`. Update all three:
  `agents/incident-commander.md` (currently says both `.eaos/memory/incidents/…` and
  `.eaos/incidents/…/RCA.md`), `playbooks/incident-response.md:31`.
- Accept: exactly one canonical RCA path across the three files; validate green after template
  deletion (nothing referenced it).

### A6. Stale counts / naming drift (bug)
- `agents/README.md:3`: "11 coordination-aware engineering personas" → remove the hardcoded
  number ("the coordination-aware personas in this directory").
- Accept: no hardcoded persona count anywhere (`grep -rn "11 " agents/README.md` clean).

### A7. Validator upgrades (prevents recurrence of A1/A3/A4/A5-class bugs)
Extend `scripts/validate-eaos.py`:
1. **Orphan templates**: every `templates/*.md` must be referenced by ≥1 non-template file;
   else warning.
2. **Path convention**: flag `artifacts/<` or `memory/` runtime paths in `agents/*.md` that
   lack the `.eaos/` prefix.
3. **Filename↔name consistency**: for each `agents/*.md`, if frontmatter `name` ≠ file
   basename, require the basename to appear in `scripts/eaos-doctor.sh`'s list (or simply
   assert doctor's `need_agents` entries all exist as `agents/<entry>.md`).
4. **Phase-table participants ⊆ roster**: in each playbook, agent names in phase tables must
   appear in the roster block (catches the release/tech-writer class).
5. **setup.sh installs every command**: each `commands/*.md` basename must appear in `setup.sh`.
- Accept: `make validate` green on the fixed repo; intentionally re-breaking A1 (rename one
  entry) makes it red.
